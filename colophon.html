01 / STUDENT A

How we structured the tasks

TASK TEMPLATE

There is exactly one task.html. Every task card in the catalog points at it, and JS later fills it from ?id= — so the criteria table had to be designed as data from day one: one row, one atomic check, one weight.

task.html — criteria row
RUBRIC SCHEMA 
<tr data-criterion="format" data-weight="0.25">
  <th scope="row">Output format</th>
  <td>Is the response format specified?</td>
  <td class="mono">25%</td>
</tr>

The data-* attributes are the contract with the future scorer: the same attributes the JS engine reads when it aggregates a weighted median.

02 / STUDENT B

How we worked with Git

WORKFLOW

Three students, one stylesheet each, zero merge conflicts in CSS: pages compose base → shared → personal, so a personal layer never edits another student's selectors.

terminal
GIT 
$ git checkout -b feature/student-c-leaderboard
$ git add styles/student-c.css leaderboard.html
$ git commit -m "leaderboard: workspace layout, rank legend"
$ git push origin feature/student-c-leaderboard

Branch naming follows feature/<student>-<page>; every PR is reviewed against the section 8 checklist in tz.md before merging into main.

What the browser shows
